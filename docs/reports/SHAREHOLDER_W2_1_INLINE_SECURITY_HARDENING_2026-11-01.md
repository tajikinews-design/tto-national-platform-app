# W2.1 — مقاوم‌سازی تصمیم درون‌مسیر و کنترل عدم افشا (GitHub، بدون Docker)

**تاریخ:** ۱ نوامبر ۲۰۲۶  
**شاخه مبنا:** W2، PR #69 — SHA پذیرفته‌شده `de6cf38cf5b2ec5bd4b4cd67289b2e54cab68fbf`  
**محدوده:** صرفاً محیط آزمایشی NextRequest/Nest Fastify، تصمیم‌گیر Python W1، دو مالک ساختگی در یک تعاونی، منبع شمارنده حافظه؛ بدون Route عملیاتی، پایگاه داده، Docker، Merge یا Deploy دستی.

## علت انتخاب W2.1

از بازبینی نسخه موفق W2 دو ضعف قابل آزمون مشخص شد که نباید قبل از اتصال احتمالی کنترل امنیتی به مسیر اجرایی باقی بمانند.

**۱. عبور پاسخ خام Nest از BFF:** پاسخ Nest قبلاً از چند کنترل کلی عبور می‌کرد ولی فیلدهای اضافی، شناسهٔ پیگیری نامعتبر و برخی تناقض‌های پاسخ با فهرست دقیق کنترل نمی‌شدند. امکان انعکاس فیلد غیرمنتظره به مرورگر از لحاظ قرارداد آزمون وجود داشت. در W2.1 یک sanitizer قطعی و allowlist هشت‌فیلدی ایجاد شد که **پاسخ جدید پاک‌سازی‌شده** می‌سازد؛ هر پاسخ دارای فیلد اضافی، دادهٔ غیر Null، `ALLOW` عملیاتی، `canGrantPermission=true`، UUID نامعتبر، شمارنده ناسازگار یا دلیل اجازهٔ ساختگی نامعتبر را رد می‌کند.

**۲. تغییر مجوز حین انتظار PDP:** در W2 پس از بررسی اولیهٔ proof سروری، یک فراخوانی PDP آسنکرون وجود داشت. اگر نشست، مالکیت، Party، مجوز منبع یا مجوز خواندن در این فاصله تغییر می‌کرد، کنترل اولیه برای تصمیم مثبت کافی نبود. در W2.1 کل ویژگی‌های مهم proof به شکل ساده در حافظه ثبت می‌شوند و **پس از پاسخ PDP و دوباره پس از ثبت رویداد ممیزی، بلافاصله قبل از منبع مصنوعی** با وضعیت فعلی مقایسه می‌شوند. هر تغییر به DENY و شمارنده مراجعه صفر منجر می‌شود.

## سایر کنترل‌های ایجادشده

- **رد بدون ادعای نادرست صفر مراجعه:** اگر منبع ساختگی فراخوانی شده اما پاسخ آن نادرست باشد، نتیجه داخلی `DENY,sourceTouches=1` باقی می‌ماند؛ BFF این پاسخ ناسازگار را مسدود و `503` با `sourceTouches:null` (نامعلوم) برمی‌گرداند، نه اعلام صفر جعلی.
- **محدودیت پاسخ منبع مصنوعی:** فقط `synthetic:true,record:null,persisted:false` مجاز است؛ فیلد اضافه از منبع به تصمیم قابل نمایش تبدیل نمی‌شود.
- **آزمون نفوذ پاسخ upstream:** کنترلر موقت Nest عمداً پاسخ دارای فیلد اطلاعات محرمانه و تصمیم جعلی `ALLOW` را بازمی‌گرداند. BFF باید هر دو را به 503 بی‌اطلاعات تبدیل کند. در این حالت ممکن است منبع ساختگی قبلاً لمس شده باشد؛ این آزمون اثبات «عدم افشا» است نه صفر مراجعه.
- **آزمون ابطال حین تصمیم PDP:** آزمون، PDP را در نقطهٔ معین معلق نگه می‌دارد، وضعیت `sourceApproved` را لغو می‌کند و سپس پاسخ مثبت پیشین را آزاد می‌کند. انتظار `PROOF_CHANGED` و صفر مراجعه است.
- **آزمون ابطال داخل Audit callback:** پس از ثبت مثبت اولیه، یک callback آزمایشی Party را لغو می‌کند؛ کنترل دوم باید قبل از source.read درخواست را مسدود کند.
- **حفظ آزمون‌های W2:** آزمون‌های نشست، مالکیت دو سهامدار ساختگی در تعاونی مشترک، source approval، timeout، audit failure، منع عملیات download/export/write/trade/finalize و محیط تولید همچنان الزامی‌اند.

## GitHub Actions — دستور فعلی کاربر

در `.github/workflows/tto-adaptive-ci.yml` استثنای **بدون Docker** فقط برای Draft PRهای دارای یکی از دو شاخهٔ نام‌گذاری‌شده W2 یا W2.1 باقی می‌ماند. تمام شش مرحلهٔ Docker/PostgreSQL/OCI برای این Draft PRها اجرا نمی‌شوند. Build و TypeScript و آزمون Python و Node 22 همچنان اجرا خواهند شد. PR در وضعیت Draft نگه داشته می‌شود؛ هرگاه از Draft خارج شود، استثنای GitHub Actions دیگر برقرار نیست و گیت Release کامل برای آینده حفظ شده است.

## محدودیت‌های قطعی و مرحله بعد

این W2.1 یک **آزمایش کنترلر موقت Nest و NextRequest** است، نه نصب PEP در Route اصلی Next یا Nest. ممیزی فقط در حافظه است و تغییر مجوزِ هم‌زمان خارج از حافظه، RLS واقعی، اتصال دیتابیس، اعتبار قانونی منابع و ثبت مالکیت واقعی بررسی نمی‌شود. Promise.race نمی‌تواند عملیات همگامِ `spawnSync` را متوقف کند؛ فقط وعده آسنکرون را زمان‌بندی می‌کند. بررسی timeout واقعی در محیط عملیاتی به طراحی فراخوانی قابل قطع نیاز دارد.

**گیت‌های حقوقی و عملیاتی هنوز بسته‌اند:** نبود هرگونه مجوز رسمی CHILD06/CHILD07، نبود دسترسی سهامدار واقعی، ممنوعیت معامله، پرداخت و تغییر حساب، نبود Merge و Deploy دستی. در صورت فعال بودن اتصال خودکار Vercel، ممکن است Preview جداگانه به‌صورت اتوماتیک ساخته شود؛ موفقیت Preview نه مجوز عملیاتی است و نه اجرای W2.1 در سامانهٔ واقعی.
