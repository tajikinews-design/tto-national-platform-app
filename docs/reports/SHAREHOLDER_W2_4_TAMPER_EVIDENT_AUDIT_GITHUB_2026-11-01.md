# W2.4 — قرارداد ممیزی امنیتی آزمایشی و تشخیص دستکاری

**مبنا:** W2.3، PR #72، SHA `216f5a4bf99fe6ad1cd4ea42d05b24323b94fbdb`  
**وضعیت:** Draft / GitHub Actions / داده صددرصد مصنوعی / بدون Docker و پایگاه داده عملیاتی.

## هدف و دامنه

برای کنترل تصمیم‌های دسترسی، زنجیرهٔ قابل پیگیری «پیش‌بررسی BFF → بررسی مستقل Nest → تصمیم PDP → پاسخ بسته BFF» در یک محیط موقت ایجاد شده است. شناسهٔ درخواست UUID تصادفی در طول هر چهار مرحله یکسان می‌ماند. هیچ شناسه سهامدار، تعاونی، Party، نشست، آدرس IP، کوکی، توکن، بدنه درخواست یا پاسخِ منبع در فایل ممیزی مجاز نیست.

## قرارداد رویداد

در فایل JSON Lines فقط هشت فیلد ذخیره می‌شوند:

```text
version, sequence, requestId, phase, decision, reasonCode, previousHash, hash
```

چهار فیلد آخر مربوط به نوع تصمیم/علت و پیوند زنجیره است. مقدار `SIMULATED_ALLOW` همچنان **مجوز عملیاتی نیست**؛ پاسخ BFF حتی پس از آن `403 W23_OPERATIONAL_NOT_APPROVED` می‌ماند. همه رکوردها به‌صورت قطعی سریال‌سازی شده و SHA-256 هر رکورد روی محتوای استاندارد و هش قبلی محاسبه می‌شود.

## ذخیره‌سازی موقت و کنترل شکست

فایل تنها در پوشه موقت Runner GitHub با دسترسی مالک `0600` ساخته می‌شود، رویدادها Append و `fsync` می‌شوند و سقف فایل ۶۴ کیلوبایت است. اگر بازکردن، نوشتن یا `fsync` شکست بخورد، ثبت‌کننده «خراب» می‌شود و بدون reconciliation دیگر به وضعیت مجاز باز نمی‌گردد. نبودن ثبت ممیزی در BFF مانع فراخوانی Nest/PDP می‌شود؛ نبود ممیزی Nest نیز از تکمیل تصمیم مثبت آزمایشی جلوگیری می‌کند.

**محدودیت مهم:** هش زنجیره‌ای به‌تنهایی امضای دیجیتال یا اثبات حذف‌ناپذیری نیست. اگر مهاجم بتواند هم فایل و هم چک‌پوینت را تغییر دهد، زنجیره بازنویسی‌شده ممکن است معتبر به‌نظر برسد. بنابراین راستی‌آزمایی تنها در برابر چک‌پوینت `{count,head}` که به‌صورت **مستقل** از فایل در حافظه آزمون نگهداری شده معنی دارد. این مرحله anchoring خارجی امن، امضای دیجیتال، چندنویسندگی و تضمین تداوم در برابر خرابی سخت‌افزاری را پیاده‌سازی نمی‌کند.

## آزمون‌های GitHub

آزمون اجرایی `scripts/ci/w24-offline-audit-chain.test.cjs` این موارد را کنترل می‌کند: زنجیرهٔ چهارمرحله‌ای با NextRequest و Nest واقعی در فرایند آزمایشی و PDP قابل‌لغو W2.2؛ تطبیق UUID؛ ممنوعیت اطلاعات حساس؛ رد درخواست بدون نشست یا با مالکیت/تعاونی نادرست پیش از PDP؛ شکست ممیزی؛ Timeout؛ تشخیص تغییر محتوا، جابه‌جایی، کوتاه‌شدن، رکورد نیمه‌کاره و خرابی فایل؛ و جلوگیری از ادامه ثبت‌کننده پس از خطای نوشتن.

آزمون `scripts/ci/test_w24_offline_audit_contract.py` در مسیر CI تأیید می‌کند هیچ import یا Route عملیاتی به این کتابخانه اضافه نشده است و هر شش گام Docker/PostgreSQL/OCI در شاخه Draft این مرحله Skipped می‌ماند. آزمون‌های W2، W2.2 و W2.3 نیز روی همان SHA دوباره اجرا می‌شوند.

## عدم فعال‌سازی و پیش‌نیازهای آینده

- هیچ پایگاه داده، صف، سرویس ممیزی بیرونی یا فایل پایدار Production اضافه نشده است.
- هیچ منبع رسمی، سهامدار واقعی، کیف پول، معامله، پرداخت یا گردش حساب فعال نشده است.
- هیچ Route Next.js یا ماژول اصلی NestJS تغییر نکرده است.
- این نتیجه پس از موفقیت CI فقط برای **قرارداد ممیزی آزمایشیِ دستکاری‌نمای وابسته به چک‌پوینت مستقل** پذیرفتنی است، نه برای Audit قانونی/تولیدی.
- انتقال به معماری عملیاتی در آینده مستلزم مرجع ممیزی مستقل، نگهداری و بازیابی امن، کنترل هم‌زمانی، امضای معتبر و تصدیق زمان، قواعد حفظ/حذف داده، مقررات حقوقی و تأیید مستقل است.
