# بازبینی NAV-03 — گیت تعاملی و بصری واقعی Chromium

## آنچه بررسی کد نشان داد و اصلاح شد

- وضعیت «تکمیل‌شده فرضی» در CSS قدیمی با پس‌زمینه سبز نمایش داده می‌شد؛ این رنگ می‌توانست نتیجه قانونی واقعی را القا کند. رنگ به خنثی آبی و حاشیه خط‌چین تبدیل شد؛ متن «هیچ مالکیت واقعی جابه‌جا نشده» بدون تغییر ماند.
- حاشیه انتخاب پرونده، سمت چپِ وابسته به جهت LTR بود؛ با `inset -4px` اصلاح شد تا انتخاب در راست‌به‌چپ روشن باشد.
- رشته‌های طولانی ممیزی/شناسه‌ها `overflow-wrap:anywhere` گرفتند. فقط تغییر UX انجام شده، **نه تصمیم حقوقی، API یا معامله**.
- بررسی بصری دستی واقعی در این محیط انجام نشده؛ بنابراین تصویرگیری و تست تعاملی اکنون به‌عنوان **گیت اجرایی در اولین Release روی SHA جدید** نصب شده است.

## آزمون Playwright / Chromium که اضافه شد

`scripts/e2e-shareholder-nav03-visual-review.cjs` در همان محیط Docker خصوصی Chromium موجود بعد از فاز 4C اجرا می‌شود. کل HTTP به `127.0.0.1:32973` محدود است؛ بدون پورت منتشرشده و بدون داده واقعی.

| محور | معیار دقیق |
|---|---|
| دسکتاپ | viewport `1440x900`؛ SSR/React و کارت‌های ۹ پرونده، screenshot و overflow |
| تبلت | viewport `768x1024` |
| موبایل | viewport `390x844` |
| موبایل کوچک | viewport `320x740` |
| انتخاب و فیلتر | ۶ مورد خرید و ۳ فروش، تغییر پرونده اختلاف و ثبت دفتر |
| کیبورد | `focus + Enter` برای فیلتر فروش و انتخاب پرونده لغو |
| معنا و امنیت | عدم انتقال از `REGISTER_RECORDED`، ۲۱ رویداد فرضی تکمیل معامله، غیرقابل‌کلیک ماندن اقدام |
| React و حریم خصوصی | نبود خطای `pageerror` و نبود درخواست به origin خارجی |
| خروجی تصویری | screenshot واقعی در حافظه گرفته می‌شود؛ فقط SHA256 آن در log ثبت می‌شود؛ تصویرهای پرونده به GitHub ارسال نمی‌شوند |

سازوکار fail-closed، علاوه بر گیت‌های Python موجود، شرط `TTO_NAV03_CHROMIUM_VISUAL_VIEWPORTS=4/4` و `TTO_NAV03_CHROMIUM_VISUAL_PASS_SHA=<exact>` را به Release اضافه می‌کند. فایل `scripts/ci/test_shareholder_w1_nav03_browser_visual.py` دارای ۸ آزمون سیاست و اتصال به Runner است.

**محدودیت:** موفقیت اتوماتیک viewport/geometry و hash تصویر برابر با داوری انسانی کیفیت بصری، زیبایی فونت و تجربه واقعی کاربر نیست. برای آن، تصویرهای واقعی اجرا و استفاده موبایل/دسکتاپ باید مستقل بررسی شوند؛ `noindex` نیز کنترل دسترسی نیست.
